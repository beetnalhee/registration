# 운영 가이드

행사 운영진용 문서입니다. 개발 지식 없이 읽을 수 있게 썼습니다.

## 접수 전날

### 1. 행사 기준일 확인 (가장 중요)

`/admin` 현황판 아래 **행사 설정 > 행사 당일** 이 실제 행사 날짜인지 확인하세요.
이 값으로 참가자의 만나이를 계산해 그룹을 나눕니다. 틀리면 그룹 배정이 어긋납니다.

### 2. 마감 임박 기준 정하기

기본값은 80%입니다. 정원 20명 중 16명이 차면 참가자 화면에 🔥 마감 임박으로 표시됩니다.
슬라이더로 조정한 뒤 **저장**을 누르세요.

- 더 일찍 알리고 싶다면 → 낮춤 (예: 70%)
- 끝까지 여유롭게 보이고 싶다면 → 높임 (예: 90%)

### 3. 테스트 신청 한 건

실제로 신청해 보고 확인하세요.

1. `/apply` 에서 본인 정보로 신청
2. 화면에 그룹·회차·시간·참가번호가 나오는지
3. **이메일이 실제로 도착하는지** (스팸함도 확인)
4. `/lookup` 에서 이메일 + 전화 뒤 4자리로 조회되는지
5. `/admin/participants` 에서 찾아 **참가 취소**로 정리

### 4. 접수 중단 상태로 두기

접수 시작 시각까지는 **행사 설정 > 접수 중단**을 눌러 잠가두세요.
중단 상태에서는 모든 회차가 ❌ 마감으로 표시되고 신청이 차단됩니다.

## 접수 시작

`/admin` → **접수 시작** 버튼.

현황판은 15초마다 자동으로 갱신됩니다. 새로 고침 버튼을 눌러 즉시 갱신할 수도 있습니다.

### 현황판 읽는 법

```
1회차   21:40 ~ 22:00                      🔥 마감 임박
  남성  18 / 20  ██████████████████░░
  여성  17 / 20  █████████████████░░░

  그룹 구성
    SUMMER   남 10 · 여 9
    NIGHT    남  8 · 여 8
```

- 위쪽 남/여 막대가 **정원**입니다. 20명이 차면 그 성별만 마감됩니다.
- 아래 **그룹 구성**은 짝을 지을 때 보는 값입니다.
  같은 그룹 안에서 남녀 수가 비슷해야 짝이 남지 않습니다.
- 그룹 옆에 `±3` 처럼 표시되면 그 그룹의 성비 차이가 3명 이상이라는 뜻입니다.
  시스템이 경계 연령 참가자를 자동으로 조정하지만, 한쪽 성별만 몰리면 한계가 있습니다.

## 자주 하는 작업

모두 `/admin/participants` 에서 참가자를 눌러 열리는 상세 창에서 합니다.

### 참가자 찾기

검색창에 **이름 · 닉네임 · 이메일 · 연락처 · 참가번호** 중 아무거나 넣으면 됩니다.
아래 드롭다운으로 상태·회차·그룹·성별을 좁힐 수 있습니다.

### 회차 바꿔주기

1. 상세 창에서 **회차** 드롭다운 선택
2. **배정 변경** 클릭

참가번호가 새 회차 기준으로 다시 발급됩니다. 참가자에게 새 번호를 알려주세요.
(변경 안내 메일은 자동 발송되지 않습니다. 필요하면 **이메일 재발송**을 누르세요.)

> 옮기려는 회차가 이미 20명이면 변경할 수 없습니다. 정원은 관리자도 넘길 수 없습니다.

### 그룹 바꿔주기

같은 방법으로 **그룹** 드롭다운을 고르고 **배정 변경**. 참가번호가 재발급됩니다.

### 참가 취소

**참가 취소** 버튼 → 확인. 좌석이 즉시 반납되어 다음 사람이 들어갈 수 있습니다.
취소 안내 메일이 자동 발송됩니다.

취소한 사람은 같은 이메일·연락처로 **다시 신청할 수 있습니다.**

### 참가자가 스스로 취소한 경우

참가자는 `/lookup` 에서 **이메일 + 전화번호 뒤 4자리**로 직접 취소할 수 있습니다.
좌석이 즉시 반납되므로 운영진이 할 일은 **대기자 승격**뿐입니다.

- 접수 중일 때만 가능합니다. **접수를 닫으면 본인 취소가 막히고** 운영진 문의로 안내됩니다
- 되돌릴 수 없습니다. 참가자가 실수로 취소했다면 새로 신청해야 하고,
  자리가 이미 찼으면 대기자가 됩니다
- 누가 취소했는지는 참가자 상세의 이력에 `본인 취소` 로 구분되어 남습니다

### 대기자 승격

대기자 상세 창에는 **대기자 승격** 버튼이 나타납니다.

- 회차·그룹을 비워두면 → 본인이 고른 회차를 먼저 보고 배정
- 특정 회차를 지정하면 → 그 회차로만 시도 (빈자리 없으면 실패)

승격 안내 메일이 자동 발송됩니다.

### 이메일이 안 갔을 때

상세 창 맨 아래 **이메일 발송 기록**을 확인하세요.

- `실패` 로 표시되면 → **이메일 재발송** 클릭
- 계속 실패하면 → 이메일 주소 오타 여부 확인. 오타면 참가자에게 직접 참가번호를 알려주세요.

### 명단 내려받기

현황판 또는 참가자 관리 페이지의 **CSV 다운로드**.
엑셀에서 바로 열립니다(한글 깨지지 않음).

> 개인정보가 담긴 파일입니다. 행사 후 삭제하세요.

## 행사 당일

1. **접수 중단** 을 눌러 추가 신청을 막습니다
2. CSV 를 내려받아 회차별로 정렬해 출력합니다 (네트워크가 끊길 때의 대비책)
3. 리셉션은 `/admin/reception` 화면을 켜둡니다
4. 참가자는 참가번호(`SUMMER-2-F-013`)로 자리를 찾습니다
5. 노쇼가 생기면 → 해당 참가자 **참가 취소** → 대기자 **승격**

### 리셉션 출석 체크

`/admin/reception` (상단 메뉴의 **출석 체크**)

참가자가 오면 **닉네임 · 참가번호 · 이름 · 연락처 아무거나** 검색창에 넣고, 나온 사람의 **출석** 버튼을 누르면 됩니다. 화면에 회차와 시간이 함께 나오니 그대로 안내해 주세요.

- 상단 카운터가 회차별 `출석 / 배정` 을 보여줍니다
- **미도착** 필터를 누르면 아직 안 온 사람만 남습니다 → 노쇼 파악용
- 잘못 눌렀으면 **되돌리기**
- 같은 사람을 여러 번 눌러도 첫 도착 시각이 유지됩니다
- 담당자 여러 명이 각자 폰으로 동시에 써도 됩니다

대기자·취소자는 출석 처리되지 않습니다. 대기자가 현장에 왔다면 먼저 **대기자 승격**을 한 뒤 출석을 누르세요.

회차를 옮겨줘도 출석 기록은 유지됩니다(이미 현장에 있는 사람이므로).

### 참가번호 읽는 법

```
SUMMER - 2 - F - 013
  │      │   │    └─ 순번
  │      │   └────── 성별 (M 남성 / F 여성)
  │      └────────── 회차
  └───────────────── 그룹
```

## 참가자에게 안내해도 되는 것 / 안 되는 것

| 안내해도 됨 | 안내하면 안 됨 |
|---|---|
| 그룹 이름 (SUMMER / NIGHT) | 그룹이 나이로 나뉜다는 사실 |
| 회차·시간·참가번호 | 현재 몇 명 신청했는지, 몇 자리 남았는지 |
| 선착순이라는 사실 | 회차별 남은 자리 수 |
| 신청 가능 / 마감 임박 / 마감 | 남녀 비율 |
| 참가 가능 연령 (만 18~35세) | 경계 연령 참가자를 다른 그룹으로 옮긴다는 사실 |

시스템은 참가자 화면·이메일에 오른쪽 항목이 나가지 않도록 만들어져 있습니다.
운영진이 말로 알려주지 않는 것만 지켜주시면 됩니다.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| 신청 화면이 계속 로딩 | `/api/health` 접속 → DB 연결 문제 |
| "일시적인 오류" 반복 | Vercel 로그 확인. 환경 변수 누락일 가능성 |
| 이메일이 전부 실패 | Gmail 앱 비밀번호 만료·오타. 일일 발송 한도(약 500통) 초과 |
| 그룹이 이상하게 나뉘어 있음 | 행사 기준일(`행사 당일`)이 맞는지 |
| 로그인이 안 됨 | Supabase Authentication 에 계정이 있는지, `admins` 표에 등록됐는지 |
| 참가자가 조회를 못 함 | 신청 시 입력한 이메일·연락처와 일치하는지. 관리자 검색으로 대신 확인해 주세요 |
